## Запуск / перезапуск backend (NestJS)

Продакшн-инстанс запускается **скомпилированной сборкой** (`node dist/main`), а не `nest start --watch`.
Поэтому любое изменение в `src/` **не применяется автоматически** — нужен ребилд + перезапуск процесса.

### Перезапустить после изменения исходников

```bash
npm run build                 # пересобрать dist/
# найти процесс, держащий :3000:
ss -ltnp | grep ':3000'       # взять pid из users:(("node",pid=NNNN,...))
# (или) ps aux | grep 'node dist/main'
kill NNNN                     # плавная остановка; при необходимости kill -9
# поднять заново в detached-режиме, чтобы пережил закрытие терминала:
setsid nohup node dist/main > /tmp/optparts-api.log 2>&1 < /dev/null &
disown
```

Проверить, что поднялось:
```bash
curl -s "http://localhost:3000/api/search?article=0451103316" | head -c 200
```

### Важные нюансы

- **Порт берётся из `.env`** (`PORT=3000`).
- **EADDRINUSE на :3000** = уже запущен другой экземпляр (часто старый `node dist/main`).
  Перед стартом нового — обязательно остановить старый процесс, иначе новые сборки не подхватятся.
- `nest start --watch` можно использовать для локальной разработки, но он держит порт только если
  :3000 свободен — на этой машине обычно занят prod-сборкой.
- Если нужно проверить правки, не трогая рабочий :3000 — подними копию на другом порту:
  `PORT=3100 node dist/main`.
- Все ключи (поставщики и каталоги) лежат в `.env` и в таблице `suppliers` (колонки `config` / `secrets_enc`).
