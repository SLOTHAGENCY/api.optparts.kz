## Goal

Подключить вкладку «Заказы» (`OrdersTab`) фронтенд-админки к реальному backend `optparts.kz`: список всех заказов, детали одного заказа, ручная смена статуса, комментарий менеджера (сохранение/удаление) и действия по под-заказам поставщиков (обновить статус / повторить размещение / оформить возврат). Работаем **только во фронтенде** (`/home/mans/projects/Dana/front`). Backend уже готов и не меняется.

## Architecture

- **Клиент** `src/lib/api/ordersAdminApi.ts` — тонкая обёртка над `apiRequest`, один объект `ordersAdminApi` с методами под каждый эндпоинт + точные TypeScript-типы (`AdminOrder`, `AdminOrderItem`, `AdminSupplierOrder`, `OrderStatus`, `SupplierOrderStatusValue`, `SupplierOrderReturnStatus`, `DeliveryType`). Существующий `ordersApi` в `src/api.ts` **не трогаем** — это клиентский (покупательский) клиент.
- **UI** `src/pages/admin/tabs/OrdersTab.tsx` — `export const OrdersTab: React.FC`. Данные через `@tanstack/react-query` (`useQuery` для списка, `useMutation` для действий). Токен берётся из `useAuthStore(s => s.accessToken)`. Локальный `viewingOrder` (выбранный заказ) — `useState` внутри `OrdersTab`.
- **Ключевой факт из backend (важно для деталей):** `GET /api/orders/all` возвращает заказы через `withLabel(order)` — это менеджерский вид, где `items` и `supplierOrders` **eager-загружены целиком** и `costPrice` НЕ вырезан. Значит список уже содержит полные объекты заказов. Детали (`renderOrderDetails`) рендерим из объекта, уже лежащего в списке (`viewingOrder`), а НЕ через `GET /api/orders/:id`.
- **Почему не `GET /api/orders/:id` для деталей:** в `orders.service.ts` `findOne(id, userId)` делает `where: { id, userId }` и отдаёт `withLabelPublic` (вырезает `costPrice`). Для админа, открывающего чужой заказ, это вернёт **404**, а для своего — урежет маржу. Поэтому детали строим из данных `/all`; метод `getOne` в клиент добавляем для полноты, но UI им не пользуется (документируем это в коде комментарием).
- **Все мутации** (`updateStatus`, `upsertComment`, `deleteComment`, `refreshSupplierStatus`, `retrySupplierOrder`, `requestReturn`) в backend возвращают **полный обновлённый заказ** через `withLabel`. Используем этот ответ, чтобы (а) обновить кэш react-query списка и (б) обновить `viewingOrder`. Никаких отдельных refetch не требуется, но подстрахуемся `invalidateQueries`.

Поэтому в типах денежные поля объявляем как `number | string`, а в UI прогоняем через хелпер `toNum()` перед форматированием. Не полагаться на то, что это всегда `number`.
