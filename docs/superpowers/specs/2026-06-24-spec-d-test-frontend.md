# Spec D — Простой тестовый фронтенд (одноразовый)

**Дата:** 2026-06-24
**Зависит от:** существующий `auth/` (login/register); Spec A (search), Spec B (cart), Spec C (orders) — для соответствующих страниц
**Параллельно с:** A/B/C (кодится против задокументированных контрактов, финальный тест — после мёржа)
**Worktree:** `test-frontend`
**Umbrella-дизайн:** [2026-06-24-multi-supplier-aggregator-design.md](./2026-06-24-multi-supplier-aggregator-design.md)

## Цель

Минимальный фронт **только для ручного тестирования** API: регистрация, вход, поиск,
корзина, оформление заказа, список заказов. **Дизайн не важен.** Должен **легко
удаляться целиком** — поэтому полностью изолирован в отдельной папке.

## Принцип изоляции (ключевое требование)

- Весь фронт лежит в **отдельной top-level папке** `test-frontend/` (НЕ внутри `src/`).
- Никакой сборки/бандлера/фреймворка: статические `*.html` + один `app.js` + `fetch`.
- Подключение к бэку — **одной строкой** и **под env-флагом**, чтобы выпиливание =
  «удалить папку + удалить один блок регистрации».

## Scope

### 1. Структура папки

```
test-frontend/
  index.html      # поиск (главная)
  login.html      # вход
  register.html   # регистрация
  cart.html       # корзина
  orders.html     # список заказов
  app.js          # общий: fetch-хелперы, JWT в localStorage, рендер
  styles.css      # минимальный (необязательно)
  README.md       # как открыть и как удалить
```

### 2. Раздача (легко удаляемая)

- Вариант по умолчанию: `ServeStaticModule.forRoot({ rootPath: join(__dirname,
  '..', 'test-frontend'), serveRoot: '/test' })` — **один отдельный блок**, обёрнутый в
  условие `process.env.SERVE_TEST_FRONTEND === 'true'`.
- CORS уже `*` (см. `main.ts`), JWT — Bearer из localStorage, поэтому фронт можно
  открыть и просто как файлы. ServeStatic — для удобства (`/test`).
- **Выпиливание:** удалить папку `test-frontend/` + удалить этот один блок ServeStatic +
  убрать `SERVE_TEST_FRONTEND` из `.env`. Больше ничего.

### 3. Страницы и потоки (против контрактов A/B/C)

- **register.html** → `POST /api/auth/register` → сохранить `accessToken` в localStorage.
- **login.html** → `POST /api/auth/login` → сохранить токен; logout — очистить.
- **index.html (поиск)** → `GET /api/search?article=&brand=` → таблица: бренд, имя,
  партнёр, цена, срок, наличие, кнопка «В корзину» (точные и аналоги — двумя списками).
  «В корзину» → `POST /api/cart/items` (отправляет снапшот оффера, как требует Spec A/B).
- **cart.html** → `GET /api/cart` → список с `priceAtAdd`/`currentPrice`/`priceChanged`/
  `available`; изменить кол-во / удалить; кнопка «Оформить» → `POST /api/orders`
  (показать `409` с изменениями, если есть).
- **orders.html** → `GET /api/orders` → список заказов с под-заказами
  (`supplier_order[]`) и статусами.

### 4. `app.js` — общее

- `api(path, opts)` — обёртка над `fetch` с автоматическим `Authorization: Bearer` и
  базовым URL (`API_BASE`, по умолчанию `''` — тот же origin).
- Хранение/чтение токена, редирект на login при `401`.
- Простой рендер таблиц/форм. Без зависимостей.

## Документация (обязательно)

- `test-frontend/README.md`: как запустить (`SERVE_TEST_FRONTEND=true` + открыть
  `/test/index.html`, либо открыть файлы напрямую), и **как удалить одним движением**.

## Тестирование

- Ручной сценарий (smoke): регистрация → вход → поиск артикула → добавить в корзину →
  открыть корзину (увидеть перепроверку цены) → оформить → увидеть заказ с под-заказами.
- Автотесты не требуются (одноразовый инструмент).
