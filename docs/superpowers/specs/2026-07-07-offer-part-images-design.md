# Картинки детали на странице офферов — дизайн

Дата: 2026-07-07
Репозитории: `api.optparts.kz` (NestJS) + `front` (React/Vite)

## Контекст (проверено вживую, не по памяти)

- **Кэш авто/каталогов уже есть и работает.** `CatalogCacheService` кэширует OEM
  (модели/узлы/детали), VIN (`validateVin`, `vin`), parts-index — ключ
  `(provider, endpoint, sha256(params))`, уникальный составной индекс
  `UQ_catalog_cache_key`. В БД десятки живых записей. Строить кэш заново НЕ нужно.
- **Картинки в OEM-подборе уже работают.** Модели (напр. BMW) отдают валидные
  `img` (`https://img.parts-catalogs.com/models/bmw/1.jpg`), фронт их рендерит
  (31 картинка, 0 битых). Плейсхолдер 🚗 остаётся только у **логотипов брендов** —
  их провайдер не отдаёт (`img: null`), картинок нет в источнике (не баг).
- **VIN** ведёт в тот же OEM-flow — картинки оттуда же.
- **Единственное, чего реально нет — картинки на странице офферов (поиск).**
  Оффер = строка цены поставщика (`SupplierOffer`), поля картинки в нём нет ни у
  одного коннектора. Но картинку можно взять у **детали** (brand+article) из
  `PartsIndexService.entity(code, brand).images` — тот же кэш, что уже работает.

## Решение (утверждено: только exact + кэш)

Обогащать картинкой только `exact`-группы результата поиска. Аналоги НЕ трогать
(их тысячи; лимит PartsIndex 1000/ключ, ключи истекают ~2026-07-11).

### Backend (`api.optparts.kz`)

1. **DTO.** В `SearchGroupDto` (`src/search/dto/search-response.dto.ts`) добавить
   необязательное поле `image?: string | null` (по умолчанию отсутствует/`null`).
   Это аддитивное поле — ничего существующего не перезаписывает.
2. **Шов обогащения — `GlobalSearchService`** (`src/catalog/services/global-search.service.ts`),
   НЕ `SearchService`. Там уже есть и результат `searchService.search()`, и доступ к
   `PartsIndexService`. После получения результата в article-режиме:
   - Для каждой `exact`-группы (обычно 1–3) параллельно вызвать
     `partsIndex.entity(group.article, group.brand)`, взять `images[0]` → `group.image`.
   - `analogs` НЕ обогащать.
   - Жёсткий предохранитель: обогащать не более `MAX_ENRICH = 5` exact-групп
     (если вдруг больше — остальные без картинки, залогировать).
3. **Кэш.** `PartsIndexService.entity()` уже кэшируется
   (`provider='partsindex'`, `endpoint='/entities'`, `params={code,brand,lang}`,
   TTL `CATALOG_TTL.DYNAMIC_MS` = 24ч). Повторные поиски не тратят лимит.
   **Коллизий нет by design**: ключ включает `code`+`brand`, у разных деталей
   разный хэш; картинки авто (endpoint `/models/…`, provider `partscatalogs`)
   физически в других строках.
4. **Best-effort.** Обёртка вокруг обогащения не должна ронять поиск: ошибка,
   таймаут, `null`, нет картинки → `image: null`, результат отдаётся как есть.
   Использовать тот же `safe(...)` паттерн, что уже применяется в
   `GlobalSearchService`, либо `Promise.allSettled`.

### Frontend (`front`)

5. **Типы.** В `SearchGroup` (`src/types/catalog.ts`) добавить `image?: string | null`.
6. **Шапка группы офферов** (`src/components/OffersList.tsx`, блок
   `DENSO · IK20 · название`): слева от бренда/названия — миниатюра `<img>` через
   `resolveApiAssetUrl(group.image)` (абсолютные https-URL проходят насквозь).
   При `null`/отсутствии — компактный плейсхолдер-иконка (напр. `Package` из lucide).
   Размер ~40–48px, `object-contain`, скруглённая рамка. НЕ дублировать картинку в
   каждую строку оффера — только в шапке группы.
7. **Мобилка.** Миниатюра слева, шапка остаётся `flex-wrap`, без переполнения на 360px.

## Тестирование

- **Backend (jest, мок-репозиторий/мок PartsIndexService):**
  - exact-группы получают `image` из `images[0]`; analogs остаются без `image`.
  - `entity()` бросает/возвращает `null` → группа получает `image: null`, весь ответ
    поиска отдаётся (поиск не падает).
  - Не более `MAX_ENRICH` групп обогащается.
- **Frontend:** `tsc --noEmit` + `npm run build`; живой прогон на «ik20» — картинка в
  шапке DENSO exact-группы, аналоги без картинок, консоль чистая.
- **Лимит:** повторный тот же поиск не увеличивает счётчик запросов к PartsIndex
  (кэш-хит) — проверить по `catalog_cache` (endpoint `/entities` не растёт при повторе).

## Вне объёма (явно)

- Картинки для аналогов (лимит).
- Логотипы брендов в OEM (провайдер не отдаёт).
- Прокси/кэш самих файлов картинок на своём сервере (CDN отдаёт напрямую, HTTP 200).
- Картинка в каждую строку оффера (дубль одной и той же картинки × N — не нужно).

## Исполнение

Одна ветка (backend+front связаны контрактом поля `image`):
- **WT-IMG-be** (api): DTO + `GlobalSearchService` обогащение + unit-тесты.
- **WT-IMG-fe** (front): типы + миниатюра в шапке группы.
be мержится до fe (fe кодируется против поля `image`).

## Открытые вопросы

- Плейсхолдер при отсутствии картинки: иконка `Package` (нейтрально) — принято по
  умолчанию, при желании заменить на эмодзи/логотип бренда.
